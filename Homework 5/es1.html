Exercise 1 – Riemann and Lebesgue integration

Riemann approach: partition the domain [a,b] into n subintervals (left, right, midpoint, trapezoid sums). Lebesgue-style approach: partition the range into m levels [yk, yk+1), estimate the measure μ(Ek) of the preimages Ek = f−1([yk,yk+1)) by counting M equispaced domain samples, and sum Σ yk μ(Ek) (lower simple function; the upper one adds exactly h·(b−a), h = range/m). This is a numerical approximation inspired by Lebesgue's construction, not an exact computation of the Lebesgue integral: the measures μ(Ek) are estimated by sampling. The range [lo, hi] is the true [inf f, sup f] when it is known analytically, and the sampled minimum/maximum otherwise (1/√x).

Discussion

Same value for Riemann-integrable functions. If f is Riemann integrable, Lebesgue and Riemann integrals coincide, and both numerical approaches converge to the same number (sin x → 2, x² → 1/3, steps, |x−½|, sin x/x → Si(π) ≈ 1.85194). The table "All functions" shows this.

Accuracy and convergence. For smooth f the midpoint and trapezoid sums converge as O(1/n²), left/right sums as O(1/n). For piecewise-continuous f (steps) every Riemann rule drops to O(1/n), and exactly 0 error appears only when a jump falls on a grid node. The lower/upper pair brackets the quantised sample average; its width (max−min)(b−a)/m is the quantisation error due to the range partition, whatever the regularity of f. It is not a guaranteed bound on the true integral, because the measures μ(Ek) are estimated from M samples (error about O(1/M) for piecewise-smooth f) and, when the range is not known exactly, min/max are taken from the samples (a midpoint grid never hits the extremes of sin x on [0,π]). With M fixed, increasing m beyond the point where the bracket is below the sampling error brings no gain: the error curve flattens. That plateau is visible in the convergence chart.

Efficiency. Riemann: n function evaluations per rule, O(1) memory. Lebesgue-style: M evaluations plus an O(M + m) binning pass and O(M) memory, so for smooth 1D integrands it is clearly less efficient (it needs a measure oracle; here the grid plays that role). Its advantage is conceptual: it only needs the measure of level sets.

Where they differ. (1) Dirichlet: not Riemann integrable (every upper Darboux sum is 1, every lower sum is 0; Riemann sums depend on the tags: 1 with rational tags, 0 with irrational ones), but Lebesgue integrable with ∫ = 1·μ(ℚ∩[0,1]) + 0·1 = 0. Floating-point numbers are all rational, so a program cannot sample the Dirichlet function meaningfully; the Lebesgue value is obtained from the exact measures of the level sets. (2) Thomae: Riemann integrable (continuous at every irrational, upper Darboux sums → 0 like n−1/2), integral 0; Lebesgue gives 0 because each {f ≥ 1/q} is finite. (3) 1/√x is unbounded: it is an improper Riemann integral (left sum = ∞, right/midpoint sums converge slowly, error O(n−1/2)), while it is a plain Lebesgue integral. Riemann rules must treat the singular endpoint separately (right/midpoint sums avoid evaluating f(0), the left and trapezoid sums are ∞). The range-partition sum takes the sampled maximum as the top of the range, so it cannot see the part of the tail above that value: it is effectively a truncation, and its error shrinks only as M grows (more samples near 0 reach higher values). (4) The indicator step shows the difference in cost vs. accuracy: Lebesgue sees only two level sets and is exact up to the sampling of the jump point.
