1. What the program does

    
The program takes the toy curve y² = x³ + 7 (mod 17), a base point G and a private key k, and computes the public key Q = kG by repeated elliptic-curve point addition. With G = (1,5) and k = 6 the sequence is 1G = (1,5), 2G = (2,10), 3G = (5,9), 4G = (12,1), 5G = (12,16), 6G = (5,8), so the toy public key is Q = (5,8). A double-and-add routine computes the same result with about log₂(k) doublings and additions instead of k additions, and the program checks that both methods agree. In Ethereum the same idea is used on secp256k1 with a 256-bit private key.


    
2. What the experiments show

    
    
      
  • Small order. G = (1,5) has order 9, so 9G is the point at infinity and kG = (k mod 9)G. Only 8 distinct points appear, however large k is. The frequency histograms therefore count each point equally often and say very little about uniformity.
    • 
      
  • Distribution of x and y. Only values that appear as coordinates of curve points can occur, so the histograms are irregular by construction. Over this tiny sample, "apparently uniform" or "not uniform" is not a meaningful conclusion.
    • 
      
  • Bits. Coordinates are below 17, so 5 bits suffice and the top bit is 1 only for the value 16. Bit frequencies cannot be 50% for that bit, which is a property of the small field, not of the function.
    • 
      
  • Correlation between k and the output. The Pearson coefficients between k and x or y are computed from the data. For k = 1…8 the sample is tiny, so the values are weak evidence either way.
    • 
      
  • Avalanche-like behaviour. The mean number of bits changed between kG and (k+1)G is compared with 2.5, the expected value for two random 5-bit numbers. Even if the result looks close, it comes from a very small sample and is not a design property.
    • 
      
  • Other base points. The menu lets you choose any curve point as G. Orders differ, so the number of reachable points changes, but the same conclusions hold.
    • 
    


    
3. Which properties matter for a cryptographic one-way function

    
    
      
  • Determinism: the same k and G always give the same Q.
    • 
      
  • Efficient forward computation: Q = kG takes about log₂(k) group operations with double-and-add.
    • 
      
  • Hard inversion: recovering k from Q is the Elliptic Curve Discrete Logarithm Problem (ECDLP). Here it is trivial, since one tries at most 9 values. On secp256k1 the group order is about 2²⁵⁶, and no known classical algorithm solves it in feasible time.
    • 
      
  • Large group order: this is what the toy example lacks and why it offers no security.
    • 
    


    
4. Which properties are specific to cryptographic hash functions

    
    
      
  • Avalanche effect: flipping one input bit should flip about half of the output bits. kG is not designed for this.
    • 
      
  • Collision resistance and second-preimage resistance: a hash must make it hard to find two inputs with the same output. For kG with k reduced modulo the order, distinct k values give distinct points, so there are no collisions in that range. The notion belongs to hashes, which compress arbitrary-length inputs into a fixed length.
    • 
      
  • Fixed-length, uniformly looking output for arbitrary input: a hash accepts messages of any length. Scalar multiplication takes a number k and returns a point of a specific group.
    • 
      
  • No algebraic structure: a good hash has none that can be exploited.
    • 
    


    
5. Why kG is not a hash function

    
The map k ↦ kG is a group homomorphism: (a+b)G = aG + bG. The program verifies this on an example. This structure is what makes public-key cryptography possible, for example in key exchange and signatures, but it is the opposite of what a hash function wants. A hash function is built so that no relation between inputs shows up between outputs. Scalar multiplication is therefore a one-way function whose hardness rests on a number-theoretic problem (ECDLP), while hash functions rely on diffusion and confusion and on empirical cryptanalysis. They share one-wayness, but not the other properties listed in section 4.


    
6. Conclusion

    
The toy example illustrates the mechanics of Q = kG and the geometric meaning of point addition. It does not support real security or statistical claims, because the group is far too small. Statistical tests such as uniformity, bit balance and avalanche are meaningful for hash functions and pseudorandom generators. For an elliptic-curve one-way function the relevant property is the computational hardness of the ECDLP in a group of large prime order.
